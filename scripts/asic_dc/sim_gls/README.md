## Cluster Usage

```bash
bash sim_gls/run_gls_smoke.sh func routerl1
bash sim_gls/run_gls_smoke.sh sdf routerl1
bash sim_gls/run_gls_smoke.sh sdf noc16
bash sim_gls/run_gls_smoke.sh func wormhole_minimal
bash sim_gls/run_gls_smoke.sh sdf wormhole_minimal
```

Or from the local repo:

```bash
GLS_SMOKE_STAGE=all|func|sdf|sdf_noc16|sdf_noc16_probe|sdf_routerl1_probe|timing \
  python scripts/asic_dc/upload_and_run_gls_smoke.py
```

Useful debug probe for RouterL1 gate-level SDF:

```bash
GLS_PROBE=1 bash sim_gls/run_gls_smoke.sh sdf routerl1 /home/ghy19/Asynchronous_Router/sim_gls/cases/smoke_sdf_1pkt.case
```

`GLS_PROBE=1` adds `+define+GLS_GATE_PROBE` and prints RouterL1 internal handshake probes for input port 0 plus selected IPM/OPM boundary signals. Keep it off for normal smoke runs.

RouterL1 DUT-boundary Head E2E probe (default path matches `smoke_directed_sdf` first packet: input0 → output4):

```bash
GLS_E2E_PROBE=1 bash sim_gls/run_gls_smoke.sh sdf routerl1
# or
GLS_SMOKE_STAGE=sdf_routerl1_probe python scripts/asic_dc/upload_and_run_gls_smoke.py
```

Override ports with `GLS_E2E_SRC_PORT` / `GLS_E2E_DST_PORT`. Prints `E2E_EDGE_REQ_NS`,
`E2E_EDGE_VALID_NS`, `E2E_WRAPPED_NS` (=`T_router`), and `E2E_WRAPPER_OVERHEAD_NS`.

NoC16 edge E2E probe for the 00->33 SDF smoke path:

```bash
GLS_E2E_PROBE=1 bash sim_gls/run_gls_smoke.sh sdf noc16
```

The default probe prints direct DUT boundary timing (`E2E_EDGE_REQ_NS`,
`E2E_EDGE_VALID_NS`) in addition to wrapper-observed `E2E_WRAPPED_NS`.
Inter-router segment probes are compiled only with `GLS_ROUTE_PROBE=1`; keep
that off unless the post-synth netlist hierarchy has been checked, otherwise
VCS can fail with XMRE on optimized-away internal nets. PrimeTime reports for
the same path are generated by:

```bash
/soft/synopsys/prime/V-2023.12/bin/pt_shell \
  -f scripts/timing/run_pt_noc16_e2e_timing.tcl \
  > logs/pt_noc16_e2e_timing.log 2> logs/pt_noc16_e2e_timing.err
```

Flags: `+notimingcheck +no_notifier`; SDF also uses `+pulse_e/0 +pulse_r/0`. Do not use `+nospecify`.

SDF is applied via a generated `sdf_boot` module because VCS requires a string-literal path in `$sdf_annotate`, not via TB plusargs.

Patch tool: `patch_gls_netlist.py --mode func|sdf`. It writes `*_post_func.v` / `*_post_sdf.v` only and never overwrites DC `*_post.v`.
