# 64 节点实验计划（精简完整消融版）

> 更新日期：2026-09-15  
> 正式设计名称：**PROP_temp64 B8**  
> 目标：用最少的实验和版面，完整回答论文的核心因果问题；不追求把所有配置、负载和 benchmark 排成大矩阵。

## 1. 从论文主线反推实验

论文的系统逻辑是：固定深度 Q64 hierarchy 提供较短的局部路径；有限数量的并行物理 lane 缓解层级汇聚；phase-safe dynamic lane binding 在拥塞下利用这些 lane；native multicast 在分支点共享公共路径；异步实现最终需要以 post-synthesis 性能、面积和能量说明其工程代价。

因此 64 节点实验只回答四个问题：

1. **Topology / bounded fatness：** PROP_temp64 相比 FlatMesh64 和 PFAT64 是否形成更好的 latency–throughput–cost 折中？
2. **Dynamic lane binding：** 在完全相同的 B8 拓扑和物理 lane 下，Dynamic 与 Static4 的真实差异是什么，拥塞时的 lane 使用和等待如何影响结果？不得预设 Dynamic 更优。
3. **Native replication：** 在同一 PROP_temp64 硬件上，Native Multicast 是否优于 source repeated-unicast？

Async/Sync B8 不再是本轮必须回答的问题。它保留为时间充足时的修复性 implementation reference；在取得同构、MAXIMUM-SDF full-drain 证据前，不形成论文主结论，也不占用主图表或阻塞其余 64 节点证据。

BC、Hotspot10 和 fanout 只作为边界检查，不再扩成独立的大型实验矩阵。

## 2. 变量隔离与配置关系

| 组别 | 与 Full PROP_temp64 的差异 | 论文中回答的问题 |
|---|---|---|
| Full PROP_temp64 B8 | Dynamic lane selection + native multicast + async | 完整设计 |
| Static4 | 只把上行 child-direction→parent-output 改为固定映射 | Dynamic lane binding 是否必要 |
| PFAT64 | 改变 hierarchy fatness / arbitration cost | 是否需要无界加宽 |
| FlatMesh64 | 改变 topology | 固定深度 hierarchy 是否有价值 |
| Repeated-Unicast | 硬件不变，只改变 multicast 实现方式 | Native replication 是否有价值 |
| Sync PROP_temp64 B8 | 拓扑、lane、buffer、routing 不变，只改变控制时序 | Async 实现的代价与收益 |

Static4 的固定规则仅作用于 `child ingress → parent output`：

```text
child direction 0/1/2/3 -> parent output lane 0/1/2/3
```

所有 `parent ingress → child output` 继续按目的地址路由，不能形成双向 lane ownership，也不能删减任何 L1–L2 或 L2–L3 物理连接。

## 3. 统一实验协议

除非某节明确说明，所有 network case 固定：

- 64 nodes、28-bit flit、5-flit packet；
- seed `202701`；
- 1000 warmup + 10000 measurement original transactions；
- packet-header arrival interval 服从指数分布；
- 一个 packet 内 Body/Tail 在 Header 后连续发送，不人为加入 flit gap；
- paired DUT 使用同一 canonical trace 和相同 measurement window；
- load 点使用 `M` 编号，不能把 M 值直接写成实际 delivered throughput；
- latency 正向结论只使用 delivery ratio ≥99% 且 measurement backlog ≤5 flits 的点；
- 饱和点只用于 delivered-throughput/saturation 结论，并标记为 censored；
- post-synthesis 结果必须通过 MAXIMUM-SDF、零 timing/annotation/X/scoreboard 错误门槛。

## 4. A — Topology 与 bounded-fat 主结果

### 研究问题

PROP_temp64 B8 是否在 FlatMesh64 的长路径与 PFAT64 的过度加宽之间形成合理折中？

### 对比与实验量

- DUT：PROP_temp64、PFAT64、FlatMesh64。
- Benchmark：Uniform Random Unicast。
- 性能：复用/补齐现有 30 点 load sweep，不新建另一套 load 网格。
- Robustness：只使用已完成的 BC、Hotspot10 PROP_temp64–FlatMesh64 结果；**不再补 PFAT64 的 BC/Hotspot10 全扫描**。

### 正文指标

- throughput vs offered load；
- pre-saturation mean/p95 latency；
- peak delivered throughput；
- near-lossless highest load；
- post-synthesis cell area；
- M100 的 `pJ/delivered flit`。

BC 和 Hotspot10 只汇总每个 benchmark 的 near-lossless throughput ratio，不再各放完整曲线。

### 可支持的 claim

只有当 PROP 同时表现出相对 FlatMesh 的 latency/path 优势，以及相对 PFAT 的 area/fan-in 优势时，才称为 bounded-fat trade-off；不能只凭单一吞吐量宣称全面最优。

## 5. B — Dynamic4 vs Static4 因果消融

### 研究问题

性能收益究竟来自四条物理 lane 本身，还是来自根据可用性动态选择 lane 的 phase-safe control？

### 公平性

Dynamic4 与 Static4 必须保持：

- 完全相同的 PROP_temp64 B8 Router 数和布线；
- 完全相同的四条 parent physical lanes；
- 相同 routing、buffer、flit width、delay recipe 和 traffic trace；
- 唯一变量是上行 parent-output lane 的选择策略。

Static4 冻结 DC `20260915_144500_prop_temp64_static4_dc` 和 M5/M100/M420 MAXIMUM-SDF full-drain 已通过本地 SHA-256 归档。50,000-flit measurement-offer cohort 的三点 latency 可与同 trace Dynamic4 作网表级对比；M420 的两种 DUT 均已有真实 L1/L2 parent-output Req/Ack lane counters。该证据显示 Static4 在 M420 的 p95 latency 和 lane 均衡性均优于 Dynamic4，原先假定的 Dynamic 正向 claim 不成立。

### 精简实验接口

正文只报告三个 UR 工作点，不做 Static4 全 load sweep：

1. M5：无拥塞控制点；
2. M100：统一 medium point；
3. `M_DS-high`：Dynamic/Static 同时满足 near-lossless 门槛的最高候选点。

`M_DS-high=M420` 已冻结。M160/M220/M280/M340 为 selection probe；M220 backlog=7 为 censored，不能进入正向 latency 结论。

### 指标

- delivered throughput；
- mean/p95 latency；
- measurement backlog；
- 四条 parent lane 的 utilization share；
- imbalance `max(lane load)/mean(lane load)`；
- `M_DS-high` 的 energy/delivered flit（若 PT-PX gate 通过）。

这组消融的主证据应是高负载下 latency/backlog 与 lane imbalance 的共同变化，而不是只比较单个 Router 的理想 aggregate rate。

## 6. C — Native Multicast 消融

### 研究问题

相同 original multicast transaction 下，网络内原生复制是否比 source repeated-unicast 更快、更省能量？

### 主实验：F16

- 硬件固定为 PROP_temp64；
- Native：一个 original transaction 注入一个 multicast packet；
- Repeated：同一个 original transaction 在源端生成 16 个 unicast packets；
- 两者共享 arrival time、source、16 个 destinations、packet length 和 trace hash。

为压缩实验量，只保留三个负载：

1. M5 full-drain；
2. 一个双方共同 near-lossless 的 medium point；
3. 一个展示 repeated-unicast 开始拥塞、并明确标为 censored 的 stress point。

### Fanout 边界检查

正文只保留 `F2/F16/F32` 三点，固定 M5、400 original transactions、400/400 completion、final backlog=0。F4/F8 历史结果保留在 supplement/raw archive，不占正文。

### 指标

- multicast completion latency `Tmax`；
- p95/p99 completion latency；
- useful destination-delivery throughput；
- completion ratio/backlog；
- M5 的 `pJ/original transaction`；
- 辅助指标 `pJ/useful destination delivery`。

`link_traversals` 若来自 route oracle，只能标为 model-estimated，不作为实测活动解释。

## 7. D — Async vs Sync implementation reference（可选、后置）

### 研究问题

在同构 B8 网络下，异步控制的性能–面积–能量 trade-off 是什么？这是一项 implementation reference，不是 architecture novelty 的主 baseline。

### 启动条件与精简实验接口

此项只在 A–C 主证据、Router PT-PX 和最小 network power 已闭环且仍有计算时间时启动。当前同构 Sync B8 DC/STA 已完成，但 M5 MAXIMUM-SDF smoke 只交付 6,330/55,000 flits 后 hard timeout；因此状态为 **blocked / repair optional**，不得提交 M100、`M_AS-high`、network PT-PX 或表格数值。

- DUT：Async PROP_temp64 B8、Sync PROP_temp64 B8；
- 只做 UR 的 M5、M100、`M_AS-high` 三点；
- `M_AS-high` 单独定义为 Async/Sync 共同 near-lossless high，不与 `M_DS-high` 混用；
- Sync clock 必须来自同一 library/PVT 下的 DC/STA，不人为指定；
- 旧 Sync1222/1248 不得替代同构 Sync B8。

### 指标

- mean/p95 latency、delivered throughput、backlog；
- cell area；
- M100 的 dynamic/leakage power 与 pJ/delivered flit。

仅当修复后的 M5 满足 `Total errors: 0`、`TB_RESULT PASS`、55,000/55,000 和 full-drain 后，才依次运行 M100、`M_AS-high` 与可选 M100 PT-PX；不以旧 Sync1222/1248 或 timeout 延长替代该 gate。
